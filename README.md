# みんなで運べ！

全員で1つの大きな荷物を持って、障害物のあるコースをゴールまで運ぶ協力ゲーム。スマホでリンクから参加する。2〜8人、1回およそ1〜2分。

画面は 3D（Three.js）。運び手の少し後ろ・低めから、進む先を見る追いかけ視点。WebGL が使えない端末では、真上から見た 2D の描画に自動で戻る（`?2d` を付けると 2D で確かめられる）。

## 遊び方

1. ホストが部屋を作り、招待URL（`/r/コード`）を送る。全員そろったらコース（5つ）と荷物（4つ）を左右の矢印で選んでスタート。ホストの選択は参加者の画面にも出る
2. 1人に1つ、荷物の持ち手がランダムに割り当てられる（前・後ろ・左・右…）。カウントダウン中に「あなたは『前』を持つ」と出る
3. 画面下のスティックで、自分の持ち手を押す向きを決める（PC は矢印キーか WASD）
4. 全員の力を足した向きに荷物が進み、持ち手の位置で回る。ばらばらに押すと回り出す
5. かけ声ボタン（せーの・右回り・左回り・止まって・ゆっくり・ナイス。PC は数字キー 1〜6）を押すと、全員の画面で自分の頭の上に吹き出しが出て音が鳴る
6. 制限時間内に、荷物の真ん中の印をゴールの枠に入れればクリア。着くと全員が跳ねて紙吹雪、結果にメダルと自己ベスト

## ルール

| | |
|---|---|
| クリア | 荷物の真ん中（白い十字の印）がゴールの枠に入る |
| 穴 | 真ん中の印が穴の上に出ると落ちる。終わりではなく、1秒落ちる様子を見せてから直前のチェックポイント（まだ通っていなければスタート）からやり直す。耐久 −15、残り時間 −5秒 |
| チェックポイント | 区間の境目の帯。真ん中が入ると通過し、残り時間が増える（+20秒、ロングコースは +15秒） |
| 失敗: 壊れた | 耐久が0になる。壁に速くぶつけると傷む（ゆっくり当てる分には傷まない）。外へ引っぱり合うと「引っぱりすぎ」で裂けて傷む。車・バー・落ちてくる荷物などに当たると横へはじかれて傷む。落ちて耐久が尽きても壊れる |
| 失敗: 時間切れ | コースごと（170〜260秒、ロングコースは570秒）にチェックポイントのボーナスが足される |
| メダル | 到着で銅。コースの基準秒以内で銀、さらに速く・耐久60以上・一度も落ちずに金。重い荷物ほど基準がゆるい（par 倍） |
| 余韻 | 到着・破損・時間切れのあと 1.6 秒は演出を見せてから結果画面へ |
| スコア | クリア: 1000 + 残り秒×10 + 耐久×5。失敗: 進んだ割合×5 |
| 個人成績 | 息ぴったり率（押している間、自分の持ち手の動きと押す向きがそろっていた割合） |

荷物（5つ。ロビーでは木箱から選び始める。サーバーの既定はソファ）:
- 木箱: 120×92。金具つき。重い（質量1.3）が丈夫（傷み0.8倍）。耐久110
- マットレス: 160×60。軽い（質量0.75）・丈夫（傷み0.45倍）。でも一番長い
- ソファ: 150×56。ドア（幅140）と細い通路は縦にしないと通らない
- 水槽: 110×72。重くて遅く（質量1.45倍）、ぶつけると2.2倍傷む。傷むと魚が慌てる
- ピアノ: 130×84。とにかく重い（質量1.9倍）。耐久140

コース（6つ）: どれも3つの区間（易しい → 仕掛けが重なる → 山場）で、区間ごとに新しい仕掛けを1種類ずつ足していく。区間の境目にチェックポイント。
| コース | 区間1 | 区間2 | 区間3 |
|---|---|---|---|
| 倉庫から新居まで | 狭いドアと穴 | ジグザグの壁と柱、細い通路 | 回るバー2本、幅120の通路と穴 |
| 商店街の横断歩道 | 車止め、工事の穴、細い路地の坂 | 車道（中央の島で待てる） | 踏切（遮断機が下りている間に電車）、速い車道 |
| 雪の坂道と川 | 氷の穴、坂のジグザグ | 手すりの無い橋、除雪車 | いかだ（動く床）で川を渡る |
| 工場のベルトコンベア | 穴へ流すベルト（左右） | 飛び出すピストン、フォークリフト | 強弱がある送風機、影で予告して落ちてくる荷物 |
| マンションの階段 | 階段と吹き抜け | 歩く住人、開け閉めする防火シャッター | 崩れる床（乗ると2.6秒で抜け、6秒で戻る） |
| 引越し大移動（ロング） | 上の5つの区間を倉庫→商店街→雪→工場→マンションの順に11区間つなぐ。チェックポイント10個 | | |

コースは `public/stages.js` の区画（幅1000の部品）を下から積んで組み立てる（`build()`）。同じ区画をロングコースでも使う。

全30通り（6コース×5荷物）を、2人と8人の自動操縦が制限時間内にゴールまで運べることを `npm test` で確かめている（自動操縦の秒数: ソファで 80〜120秒、ロングは 267秒。ピアノはその約2倍）。

## 人数で変わるところ

- 持ち手は人数ぶん、荷物の外周に等間隔で並ぶ（2人なら前と後ろ、4人なら前・左・後ろ・右、8人なら角と辺の真ん中）
- 1人の力は「全体の力 ÷ 人数」。全員そろえば何人でも同じ速さで進み、1人だけ押すと 1/人数 の力しか出ない
- 途中で抜けた人の持ち手は止まり、残りの人数で力を分け直す。全員抜けると終わる

## 動きのしくみ

- 荷物の位置・向き・速度はサーバーだけが持つ。各プレイヤーは「押す向き（長さ1以内）」だけを送る
- サーバーは 60Hz の固定ステップで、全員の力の合力（進む）とトルク（回る）から荷物を動かす。速度と回転には減衰があり、手を離すと止まる
- 壁との当たりは、荷物の外周の点（10単位おき）と壁の角で調べ、撃力で跳ね返す。ぶつけた強さは撃力を当てる前の速さで測り、1回の衝突を二重に数えない
- 操作が 0.8 秒届かない人は手を離したとみなす（切断した人が押しっぱなしにならない）
- 画面へは 20Hz で状態を送る。画面は 110ms 遅らせて前後の状態を補間して描く（角度は近い向きに回す）
- 効果音（ぶつけた音・カウントダウン・クリア/失敗）と短い BGM は Web Audio で鳴らす。右上のボタンで消せる（端末に記憶）
- 画面に毎回送るのは荷物の位置・向き・耐久と各持ち手の押す向き、かけ声だけ（8人で700バイト未満）。コースの形は `public/stages.js` を画面側も読む
- 動く障害物の位置はスタートからの秒数だけで決まる（`moverAt`）。サーバーと画面が同じ式で計算するので、障害物の位置は送らない
- 床の仕掛けは荷物の真ん中がある所の効果がかかる: 氷=減衰0.15倍、階段=減衰+2、ベルト=ベルトの速さへ毎秒2の強さで引き寄せる
- 進んだ割合はコースの通り道（`path`）に沿って測る（折り返すコースでも正しく出る）
- BGM はコースごとに音の並びと速さを変える

## 3D の見た目（`public/view3d.js`）

- ワールドの x → 3D の x、y → 3D の z（1単位 = 1cm）。サーバーの 2D 物理をそのまま立体で見せる
- カメラ: 荷物の南（手前）の低い所（俯角38度）から北を見る。向きは固定なので「スティックの上＝画面の奥」がずっと同じ。通り道が手前へ戻る区間（マンションの下り）では自動で高く上がって見下ろす。右上の虫めがねで引きの視点に切り替え
- 荷物より手前の壁は上を切り取り、荷物の手前に立つ運び手は半透明にする（低い視点でも荷物の向きが見える）
- 床は 2D の描き方で1枚の絵を作って貼る。穴はその部分を透明にして、下に深さのある箱（雪のコースは水面）
- 運び手: 頭の大きいちびキャラ。帽子（キャップ・ニット帽・ヘルメット）と服の色は持ち手の色。手袋の腕2本で持ち手を握る。表情は 普通／叫ぶ（押している）／歯を食いしばって汗（押しても動かない）／不安（耐久が少ない）／驚き（落下・破損）／笑顔（到着）
- 壊れる飾り（コーン・タイヤ・小箱）は通り道の脇に置き、荷物か運び手が近づくと吹き飛ぶ。画面だけの演出で、荷物は傷まず進路もふさがない
- ゴールは紅白の柱と GOAL の幕、旗、行き先ののれん。横断歩道のコースの奥はラーメン屋
- トゥーン（3段の陰影）と輪郭線。空は上が濃い青のグラデーションと雲
- 重さ対策: 画素比の上限（画質 高2 / 中1.5 / 低1）、影は1灯、壁や段は InstancedMesh。fps が 42 を切ると画質を1段下げる（スマホは中から始める）
- 名前の札とかけ声の吹き出しは HTML を 3D の頭の上に重ねる
- 床の絵は縦 16m ずつの板に分け、カメラの近くの板だけ作る（ロングコースでも画質を落とさず、メモリも食わない）。壁・小物・穴の見た目は場所のテーマ（regions）で変わる
- 仕掛け: 回るバー（紅白の棒）、防火シャッター（下りてくる）、踏切（棒が倒れて赤く点滅、電車が通る）、落ちてくる荷物（床の影が濃くなり、クレーンから落ちて跳ねる）、いかだ、崩れる床（きしんで揺れ、抜けて落ちる）、送風機（羽根が回り、風の筋が流れる）、チェックポイントの旗（通ると緑）
- 穴に落ちると荷物が沈んでいき、チェックポイントに戻るとカメラも一緒に移る。画面に「落ちた！」「チェックポイント +20秒」の帯
- ミニマップは長いコースでは荷物のまわり（約32m）だけを映す

## 起動

```
npm install
npm start
```

ブラウザで http://localhost:8104 を開く。ポートを変えるときは `PORT=8080 npm start`。

同じ Wi-Fi のスマホから遊ぶときは、Mac の IP で開く（例 http://192.168.0.10:8104）。

## テスト

```
npm test             # ルール・部屋・通信の単体/統合テスト（49件）
npx playwright install chromium webkit   # 初回だけ
node tools/e2e.mjs   # 実ブラウザ（chromium と webkit）で3人プレイを最後まで通す
```

`tools/e2e.mjs` は、作成→招待URLで参加→コースと荷物の選択（参加者にも見える）→開始→スティックとキーボードの操作が全員に届く→かけ声が全員に届く→自動操縦で横断歩道コースをゴールまで運ぶ→メダルと自己ベスト→再戦 を通し、各画面が 390x844 / 360x640 / 844x390 / 568x320 で上下にスクロールせず収まるかを数値で確かめる。スクショは `tools/shots/`。

`tools/autopilot.mjs` はテスト用の自動操縦（コースの `path` をたどり、動く障害物は時刻から位置を予測して手前で待つ）。ゲーム本体は使わない。
`node tools/sim-all.mjs` で全コース×全荷物×人数の結果（秒・耐久・当たった回数・メダル）を表にできる。メダルの基準秒はこれを見て決めた。
`node tools/trace.mjs <コース> <荷物>` は1回分の位置と事故を秒ごとに出す（詰まる場所を探す用）。
`node tools/shot-courses.mjs` は5コースの盤面を撮る（`W=844 H=390` で横画面）。`node tools/shot-ui.mjs` はホーム・遊び方・ロビーを4サイズで撮る。
`node tools/fps.mjs` は GPU を使う headless Chromium で、スマホ相当（390x844・画素比3）と横持ちの fps を全コースぶん測る。
`node tools/shot-hazards.mjs [名前]` は、仕掛けのある場所（回るバー・踏切・落ちてくる荷物・いかだ・崩れる床・送風機・チェックポイント・ゴール・ロングコースの街の切り替わり）の 3D 画面を、通しで遊ばずに撮る。

OGP画像は `node tools/make-og.mjs` で `public/og.png`（1200x630）を作り直せる（4人で運んでいる 3D の画面に、タイトルのロゴと一言を重ねる）。

Three.js は `public/vendor/`（r185、MIT）に置いてある。CDN には頼らない。画面の文字は Google Fonts（Dela Gothic One / M PLUS Rounded 1c / Yomogi）を読み、読めないときは端末の日本語フォントで出る。

## コースや荷物を足す

`public/stages.js` にデータとして書く。

- コース: 区画を並べて `build({ sections: [[区画, ...], [区画, ...], [区画, ...]] })` で作り、`COURSES` に足すとロビーの選択肢に出る。区画が持てるもの（walls・pits・zones・movers・spinners・gates・drops・platforms・crumbles・path）は `stages.js` の冒頭に書いた。足したら `NOLIMIT=1 node tools/sim-all.mjs <id>` で全荷物の秒数を見て、timeLimit と medals を決める
- 仕掛けの当たり判定はサーバー（`lib/game.mjs`）、予測は `hazardAt`（`stages.js`。自動操縦の待ち合わせに使う）、見た目は `game-view.js`（2D）と `view3d.js`（3D）
- 荷物: `CARGOS` に `{ name, lead, w, h, mass, fragile, hp, par, color }` を足すと、ロビーの選択肢に出る（描き分けは `game-view.js` の `drawCargo`）

## デプロイ

このフォルダ1つが1つのサービス。WebSocket が使えるホスティングが必要（静的ホスティング不可）。

- Render: `render.yaml`（Blueprint）。リポジトリのルートがこのフォルダでない場合は `rootDir: carry-together` を足す
- Fly.io / Cloud Run など: `Dockerfile`（ポート 8080）
- ヘルスチェック: `/healthz`
- `og:image` は届いたホスト名（`X-Forwarded-Host` / `Host`）で絶対URLに書き換えて返す

いまは手元の Mac から cloudflared のクイックトンネルで公開している（`../publish.sh`。URL は起動のたびに変わり、Mac が起きている間だけつながる）。
